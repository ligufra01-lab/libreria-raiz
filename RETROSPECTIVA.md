# Retrospectiva — Librería Independiente Raíz

> **Documento de retrospectiva académica.** Esta síntesis recoge el análisis del caso y las prácticas aplicadas/propuestas; no es una transcripción de una reunión real.

## 1. ¿Qué funcionó bien?

- La priorización MoSCoW ayudó a distinguir las funciones esenciales de las mejoras que podían aplazarse.
- La separación del sitio en secciones facilitó organizar el contenido y la navegación.
- El uso de ramas y Pull Requests permitió proponer cambios sin trabajar directamente sobre `main`.
- La publicación con GitHub Pages permitió disponer de una URL pública para revisar el sitio.
- La documentación básica del repositorio ofrece un punto de partida para que otro integrante conozca el proyecto.

## 2. ¿Qué se debe mejorar?

- Preparar y actualizar el README desde el inicio, no únicamente al final.
- Definir responsables y fechas para cada tarea antes de comenzar el sprint.
- Coordinar previamente la edición de archivos compartidos, especialmente hojas de estilos.
- Realizar pruebas de navegación, enlaces y adaptación responsive antes de integrar cada Pull Request.
- Diferenciar claramente las funcionalidades demostrativas de aquellas conectadas a servicios reales. En particular, el formulario actual valida en el navegador, pero no cuenta con un backend para recibir o almacenar mensajes.

## 4. Conclusión

La retrospectiva permite convertir la experiencia del proyecto en mejoras concretas. Un cierre ordenado no consiste solamente en publicar el sitio: requiere priorizar, comunicar responsabilidades, documentar, revisar el código y dejar claros tanto los resultados como las limitaciones y los pendientes.
